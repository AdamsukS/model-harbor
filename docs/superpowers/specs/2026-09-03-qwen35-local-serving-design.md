# Qwen3.5-9B 本地推理服务设计

## 目标

在 16GB Apple M4 Mac mini 上下载并运行 Qwen3.5-9B 的 4-bit MLX 量化模型，提供可供后续 Agent 调用的 OpenAI 兼容文本接口，并建立可重复的缓存与上下文实验基线。

第一阶段只交付基础推理服务。Agent 编排、长期记忆、对话摘要、用户账户、持久化任务队列和分布式部署不在本阶段实现。

## 已知环境与约束

- 主机为 Apple M4、10 核 GPU、16GB 统一内存。
- 操作系统为 macOS 26.5.1，Metal 4 可用。
- 系统 Python 为 3.14.5；运行环境必须独立使用 Python 3.12。
- 当前磁盘约有 45GB 可用空间。
- 服务只处理文本、代码、推理和工具调用，不接收图片。
- 最多有 5 个用户同时提交请求。
- 目标逻辑上下文为 128K tokens；实际可用窗口和并发度必须由内存实验决定。
- 默认仅绑定 `127.0.0.1:8000`，不暴露到公网。

## 模型

使用 `mlx-community/Qwen3.5-9B-4bit`。该模型由官方 `Qwen/Qwen3.5-9B` 转换而来，模型文件约 5.95GB，适合 Apple Silicon 的 MLX 推理。

模型下载到项目的 `models/Qwen3.5-9B-4bit/`，该目录不纳入 Git。准备流程记录下载时解析到的 Hugging Face revision，以便复现实验。下载完成后，启动脚本只使用本地路径，不依赖运行时联网。

## 推理后端

### 必须可用的基线：MLX-LM

MLX-LM 是第一阶段的可靠性基线。它负责模型加载、Metal 推理、批量生成和 Prompt Cache，并提供 OpenAI 风格的 HTTP API。

服务启动后必须支持：

- `GET /v1/models`
- `POST /v1/chat/completions`
- 非流式文本生成
- SSE 流式文本生成
- 多轮消息输入
- 最多 5 个客户端同时提交请求；后端可根据可用内存串行或小批量执行

MLX-LM 自带服务不作为安全边界。第一阶段仅允许本机访问；未来需要局域网或公网访问时再增加独立网关、鉴权、限流和持久化队列。

### 可选加速实验：SGLang + MLX

按照 SGLang 官方 Apple Metal 路径，在独立环境中尝试加载同一份本地 MLX 模型。启动参数启用 MLX、关闭 CUDA Graph，并保持与基线相同的监听地址和模型别名。

SGLang 仅在以下检查全部通过后才能成为默认后端：

- 模型能完整加载且无进程崩溃；
- 普通、流式和多轮请求均能返回有效结果；
- 工具调用格式可被客户端解析；
- 5 个并发短请求不会死锁或无限等待；
- 进程内存不会造成持续交换或系统失去响应；
- 相比 MLX-LM，在相同输入输出条件下至少有一项可量化收益：更高吞吐、更低首 Token 延迟或更有效的前缀复用。

如果安装、模型加载或上述验证失败，记录失败原因并保留 MLX-LM 为默认后端，不继续修补 SGLang 内部实现。

## 缓存与上下文实验

缓存是本项目后续实验的核心，因此第一阶段不隐藏后端缓存行为。启动配置与实验记录必须显式保存以下变量：

- 后端及精确版本；
- 模型 revision；
- 物理上下文长度；
- Prompt Cache 上限；
- prefill 并发度与 decode 并发度；
- 输入 tokens、输出 tokens、首 Token 延迟、总耗时和峰值内存；
- 冷缓存、相同前缀热缓存、不同前缀三种场景。

初始计划中的 5 个缓存条目/2GB 上限在 32K 对照前缀测试中触发了 1GiB swap 增长保护。经相同负载复测，默认值调整为 1 个缓存条目和 1200MB 上限；该限制只控制保留的热前缀数量，不限制最多 5 个客户端进入服务队列。

验证顺序为 32K、64K、128K。每个长度先测试单请求，再测试并发请求。若某一级别触发内存压力、明显交换、进程退出或不可接受的系统卡顿，就停止提高该组合的并发度，并保留上一个稳定组合作为默认值。

第一阶段不实现对话摘要。若原生 128K 无法稳定运行，服务仍保持可用，并把稳定的物理窗口写入默认配置；后续 Agent 层通过摘要、裁剪或外部记忆实现 128K 逻辑会话。

## 项目结构

- `models/`：本地模型快照，不纳入 Git。
- `scripts/prepare.sh`：检查环境、创建 Python 3.12 虚拟环境、安装锁定依赖并下载模型。
- `scripts/start-mlx.sh`：在后台启动默认 MLX-LM 服务，并记录 PID 与日志。
- `scripts/start-sglang.sh`：在后台启动可选 SGLang/MLX 服务并记录 PID 与日志；未安装或不兼容时给出清晰错误。
- `scripts/stop.sh`：仅停止由本项目启动并记录 PID 的服务。
- `scripts/health.sh`：验证进程、模型列表和一次最小对话请求。
- `scripts/smoke.sh`：验证非流式、流式、多轮、工具格式和 5 客户端请求。
- `scripts/bench-cache.sh`：运行冷/热前缀与不同上下文长度的缓存实验。
- `config/default.env`：安全的本地默认参数。
- `config/experiments/`：不同上下文和缓存实验参数。
- `results/`：版本化的结果说明；体积较大的原始日志不纳入 Git。
- `README.md`：准备、启动、调用、停止、故障排查和实验说明。
- `docs/API.md`：OpenAI 兼容接口、请求与响应、SSE 流式格式、错误处理、工具调用和 Agent 客户端示例。
- `docs/MODULES.md`：各目录与脚本职责、启动流程、缓存实验点、配置来源和后端替换方式。

所有脚本从自身所在位置解析项目根目录，不能依赖调用者当前工作目录。运行时文件、PID、日志、虚拟环境和模型权重均加入 `.gitignore`。

## 启动与失败处理

准备流程在下载前检查 Apple Silicon、剩余磁盘、Python 3.12 可用性和 Metal。失败时返回非零状态并说明修复方式。模型下载支持 Hugging Face 自带的断点续传；重复执行不得重新下载已完整存在的文件。

启动脚本必须防止重复启动同一端口，并把 PID 与日志写入项目运行目录。健康检查只在模型真正能完成最小推理后才报告成功。停止脚本只读取本项目 PID 文件，并在发送终止信号前核对进程命令行，避免误杀其他服务。

## 验收标准

第一阶段完成需要同时满足：

1. 本地模型文件完整，revision 已记录，断网后仍可加载。
2. MLX-LM 服务可通过一个命令启动，并通过 `/v1/models` 和最小聊天请求。
3. 流式、多轮和 5 客户端请求测试完成且没有请求永久挂起。
4. 至少完成 32K 的缓存基准；64K 和 128K 按主机稳定性逐级测试并如实记录结果。
5. 冷缓存与共享前缀热缓存的测试方法可复现，结果包含延迟、吞吐和峰值内存。
6. SGLang 要么通过同一套基本测试，要么留下明确的不兼容记录；其失败不影响验收。
7. README 中包含 Agent 客户端所需的 Base URL、模型名和最小调用示例。
8. `docs/API.md` 足以让调用方在不阅读脚本源码的情况下完成普通、流式和工具调用接入。
9. `docs/MODULES.md` 足以让维护者定位准备、运行、缓存实验和后端切换相关代码与配置。
